## 1. 背景与目标

### 核心问题

当前产品像字典——用完即走。用户进来背一首诗，背完之后没有任何东西在等他们回来。

根因诊断（五角色一致认同）：

- 没有"今天该做什么"的明确锚点，首页是开放式内容库而非任务驱动界面
- 完成之后没有召回钩子，不回来没有任何损失
- 进度数字"已背 X 首"对 6-8 岁孩子没有情绪意义，数字不等于动力
- 缺少完成感的积累——字典是查完即走的工具，没有时间维度

### 目标

将产品从"内容库"模式切换到"每日任务"模式。具体目标：

| 指标 | 现状（估算） | v1 目标 |
|------|------------|---------|
| 次日留存率 | < 15% | > 40% |
| 7日留存率 | < 5% | > 20% |
| 当日打开后任务完成率 | — | > 60% |
| 坚持 7 天以上用户占比 | — | > 15% |

### 设计原则（全员共识）

1. **任务要小，要必定完成**：每天一首，5 分钟内完成，不能让孩子有失败体验
2. **即时可见的成就积累**：完成瞬间要有视觉+听觉爆发，延迟满足对 6-8 岁无效
3. **不惩罚，不归零**：断掉不清空，用温暖语言召回，不能给孩子和家长制造焦虑
4. **奖励服务于学习本身**：撒花、连续天数是"我又背了一首诗"的成就感的放大器，不能反客为主

## 2. 用户故事

### 主要用户：6-8 岁孩子

**US-01**  
作为一个 6 岁的孩子，我希望打开 app 就能看到今天要背哪首诗，以便不需要自己想或者问家长，直接开始就好。

**US-02**  
作为一个正在背诗的孩子，我希望背完诗的那一刻有撒花和音效，以便感受到"我做到了"的成就感。

**US-03**  
作为一个连续背了几天诗的孩子，我希望看到"已坚持 X 天"的数字每天长大，以便有继续回来的动力。

**US-04**  
作为一个昨天没背诗的孩子，我希望今天打开 app 时看到温暖的欢迎提示而不是惩罚提示，以便不会因为"断了"就彻底放弃。

**US-05**  
作为一个刚背完诗的孩子，我希望能看到整首诗的全文，以便叫家长来听我背一遍。

### 次要用户：家长

**US-06**  
作为一个家长，我希望只需要一次性设置孩子的年级，以便之后系统自动推荐合适的诗，不需要我每天操心"今天背哪首"。

**US-07**  
作为一个家长，我希望首页今日任务够显眼、够明确，以便孩子自己打开 app 就知道该做什么，我不需要全程陪同。

**US-08**  
作为一个家长，我希望孩子背完后有"已完成"的视觉状态，以便偶尔瞥一眼就知道孩子今天做了没有。

  return lastComplete !== today && lastComplete !== yesterday;
}

### 3.3 今日推荐逻辑

**算法（v1 固定顺序）：**

```js
function getTodayPoem(grade) {
  const poemList = POEM_LIST[grade]; // 按难度排序的诗目数组
  const startDate = localStorage.getItem('daily_task.start_date');
  const today = getTodayStr();
  const dayIndex = diffDays(startDate, today); // 今天是第几天（从0开始）
  const idx = dayIndex % poemList.length; // 循环，跑完后进入复习循环
  return poemList[idx];
}
```

**推荐规则：**
- 每天自动推进一首，以设备首次使用日期（`start_date`）为 Day 0
- 当天完成或未完成，第二天均推进到下一首（不补昨天的诗）
- 年级切换后，从新年级第一首重新推进，旧年级进度保留但不继续
- 跑完全部诗目后进入复习循环（从第一首重新开始）

**前 7 首固定顺序（P0 硬编码，两个年级共用）：**

| 序号 | 诗名 | 作者 | 背景介绍（15字以内） |
|------|------|------|---------------------|
| 1 | 静夜思 | 唐·李白 | 李白写的，想念故乡的夜晚 |
| 2 | 咏鹅 | 唐·骆宾王 | 骆宾王7岁写的，夸大白鹅 |
| 3 | 春晓 | 唐·孟浩然 | 孟浩然春天睡醒后写的 |
| 4 | 锄禾 | 唐·李绅 | 提醒我们珍惜每粒粮食 |
| 5 | 登鹳雀楼 | 唐·王之涣 | 爬高楼看更远的风景 |
| 6 | 相思 | 唐·王维 | 王维送给远方朋友的礼物 |
| 7 | 江南 | 汉乐府 | 很久很久以前人们采莲的歌 |

> 第 8-20 首由陈博士提供难度排序后补入配置，上线前置条件之一。

### 3.4 Streak（坚持天数）机制

**计算规则：**

```js
function updateStreak() {
  const data = loadDailyTask();
  const today = getTodayStr();
  
  // 如果今天已经算过了，不重复计算
  if (data.last_complete_date === today) return;
  
  data.streak_count += 1;
  data.last_complete_date = today;
  data.today_complete = true;
  saveDailyTask(data);
}
```

**展示文案映射：**

| 情况 | 展示文案 |
|------|----------|
| streak_count === 0，从未完成 | "今天开始第一天！" |
| streak_count > 0，正常显示 | "已坚持 N 天" |
| 断了超过 7 天回来（可选，v1 暂不区分）| "已坚持 N 天"（保持一致，不惩罚） |

**不做的事：**
- 不清零，不归零
- 不显示"连续天数中断"等惩罚性文案
- 不区分"连续"和"累计"（v1 统一用累计，文案"已坚持"而非"连续"）

## 4. 数据结构设计

所有数据存储于 `localStorage`，key 为 `poem_app_data`，value 为 JSON 字符串。

### 完整数据结构

```json
{
  "daily_task": {
    "grade": 1,
    "start_date": "2026-10-01",
    "streak_count": 12,
    "last_complete_date": "2026-10-07",
    "today_complete": false
  },
  "poem_progress": {
    "jing-ye-si": {
      "read": true,
      "memorized": true,
      "memorized_date": "2026-10-01"
    },
    "yong-e": {
      "read": true,
      "memorized": false,
      "memorized_date": null
    }
  }
}
```

### 字段说明

#### `daily_task`

| 字段 | 类型 | 说明 |
|------|------|------|
| `grade` | number | 年级，1 或 2；未设置时为 null |
| `start_date` | string | 首次使用日期，格式 "YYYY-MM-DD"；用于计算今日推荐序号 |
| `streak_count` | number | 累计坚持天数，只增不减，初始为 0 |
| `last_complete_date` | string \| null | 最后一次完成任务的日期；用于判断今日是否已完成 |
| `today_complete` | boolean | 今日完成状态；每次 app 启动时检查日期，若日期变化则重置为 false |

#### `poem_progress`

| 字段 | 类型 | 说明 |
|------|------|------|
| key | string | 诗的唯一 ID，使用拼音 slug，如 "jing-ye-si" |
| `read` | boolean | 是否已阅读过 |
| `memorized` | boolean | 是否已完成背一背 |
| `memorized_date` | string \| null | 完成背一背的日期，格式 "YYYY-MM-DD" |

### 初始化逻辑

```js
function loadDailyTask() {
  try {
    const raw = localStorage.getItem('poem_app_data');
    if (!raw) return getDefaultData();
    const data = JSON.parse(raw);
    // 跨日重置 today_complete
    if (data.daily_task.last_complete_date !== getTodayStr()) {
      // 注意：只重置 today_complete，不重置 streak_count
      data.daily_task.today_complete = false;
    }
    return data;
  } catch (e) {
    return getDefaultData();
  }
}

function getDefaultData() {
  return {
    daily_task: {
      grade: null,
      start_date: getTodayStr(),
      streak_count: 0,
      last_complete_date: null,
      today_complete: false
    },
    poem_progress: {}
  };
}
```

### 数据写入

```js
function saveDailyTask(data) {
  try {
    localStorage.setItem('poem_app_data', JSON.stringify(data));
  } catch (e) {
    // localStorage 写入失败（如私人浏览模式），静默降级，不崩溃
    console.warn('localStorage write failed', e);
  }
}
```

### 已知局限（v1 接受的技术债）

- 换设备或清除浏览器缓存后，所有进度丢失，从头开始
- 该问题需账号体系才能根本解决，v1 不处理
- 建议在首次使用引导时展示一行小字提示："建议固定在同一台设备使用"

## 5. 通知策略

### v1 结论：不做推送通知

原因（老李 + 王妈妈联合判断）：

- iOS Safari 对 PWA 通知的支持到近年才松口，真实用户授权率低于 20%
- 家长是主要授权决策者，推送过多家长会先关掉，效果适得其反
- 把留存押注在大多数用户会拒绝的权限上，是设计失败

### v1 降级方案

用**首屏显眼性**替代推送，即"打开就是正确的行为提示"：

- 今日任务卡片占首屏 55-60%，进入 app 第一眼就是今日任务
- 完成第一次任务后，展示手动设置提醒引导：

```
┌─────────────────────────────────────────┐
│  小贴士：每天固定时间背一首，效果最好！    │
│  可以在手机时钟里设一个每天的小提醒 ⏰    │
└─────────────────────────────────────────┘
```

这段文字出现在背一背完成后的"背给家长听"界面下方，静态展示，不弹窗。

### v2 规划（有数据后决策）

| 项目 | 规格 |
|------|------|
| 触发时机 | 孩子完成第一次任务后，引导家长授权 |
| 控制权 | 家长可设置推送时间段（如每天 18:00-19:00） |
| 默认关闭 | 不主动请求权限，等用户先体验到价值 |
| 文案 | "要不要每天提醒 [孩子名] 来背诗？" |

## 6. 验收标准

### AC-01：首页今日任务卡片显示

- [ ] 打开 app，首屏可见今日任务卡片（不需要滚动）
- [ ] 卡片展示今日推荐诗的诗名、作者、15 字背景介绍
- [ ] 卡片底部显示"已坚持 N 天"，N 为正确的累计完成天数
- [ ] grade 未设置时，卡片区域显示年级选择引导，不显示任务卡片

### AC-02：今日任务完成流程

- [ ] 点击"开始今天的诗"直接进入背一背模式，不经过详情页
- [ ] 背一背三关全部完成后，触发撒花动画
- [ ] 撒花后展示完整诗文 + "背给家长听"提示文字
- [ ] 点击"回首页"后，首页卡片切换为状态 B（已完成）
- [ ] 状态 B：卡片边框变绿，按钮变为"今天已完成"不可点击状态
- [ ] 状态 B：streak 数字显示完成后的新值，有 +1 标记和弹跳动画

### AC-03：Streak 数据正确性

- [ ] 首次完成任务：streak_count 从 0 变为 1
- [ ] 连续完成第 N 天：streak_count 正确递增
- [ ] 昨天未完成，今天完成：streak_count 仍然正确递增（不归零）
- [ ] 同一天第二次进入背一背并完成：streak_count 不重复计数
- [ ] 次日打开 app：today_complete 自动重置为 false，streak_count 不变

### AC-04：久违回访提示

- [ ] 最后完成日期不是昨天也不是今天，进入首页时显示"好久不见，继续出发！"横幅
- [ ] 横幅 4 秒后自动消失
- [ ] 横幅不遮挡今日任务卡片的主要内容
- [ ] 连续完成中回来，不显示此横幅

### AC-05：年级设置

- [ ] 顶栏设置图标可点击，弹出年级选择面板

- [ ] 数据结构损坏（JSON 解析失败）：使用默认值重新初始化，不崩溃

## 7. 不做什么（Out of Scope）

| 功能 | 排除原因 | 计划版本 |
|------|----------|----------|
| 家长每日手选今日诗 | 制造决策疲劳，v1 先验证固定推荐框架的留存效果 | v2（待数据决策） |
| 补做昨日未完成内容 | 增加系统复杂度；不做会给孩子造成"欠债感"，与设计原则冲突 | 不做 |
| 补签机制（每周1次） | v1 以简单性为优先，先验证核心框架 | v1.1 |
| 诗集归档视图 | 需要额外页面开发，v1 先跑通核心任务流程 | v1.1 |
| 明日诗预告 | 在撒花流程之后加屏，影响完成体验，待视觉稿确认后迭代 | v1.1 |
| PWA 推送通知 | iOS 授权率低，不适合 v1 押注；v2 在用户体验价值后引导 | v2 |
| 录音分享功能 | 技术成本高（录音权限、音频处理），"背给家长听"文字提示已覆盖核心需求 | v2 |
| 动态难度分桶推荐 | 需给所有诗打标签 + 维护完成率 + 实现升降桶，3-4天工作量；v1 无足够行为数据支撑 | v3+ |
| 账号体系 / 跨设备同步 | 需后端，超出当前纯前端架构 | v3+ |
| 家长查看报告 / 进度分享 | 单独功能模块，v2 先做完成分享图 | v2 |
| 本月完成 X 天的显示 | v1 统一用累计天数，避免逻辑复杂化 | v2 |
