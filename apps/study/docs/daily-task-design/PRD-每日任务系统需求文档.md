# 今日山·每日任务系统 需求文档

**版本**：v1.0  
**日期**：2026-10-08  
**状态**：待评审  
**背景**：本文档基于陈博士、张总、小林、王妈妈、老李五人六轮深度讨论整理产出

---

## 一、问题定义

### 当前核心问题

用户将 app 描述为"像字典"——有内容、没有召回机制、没有每日驱动力。具体表现：

- 孩子打开 app 不知道"今天要做什么"
- 完成一首诗后没有任何东西等着他回来
- 进度数字（"已背7首"）对6-8岁孩子不产生情绪
- 缺少每日回访的外部钩子

### 目标用户

- **主要使用者**：6-8岁儿童
- **次要使用者**：家长（监督、偶发参与）
- **约束**：纯前端，无后端，数据存 localStorage，换设备数据会丢失

---

## 二、设计原则

根据讨论确立的核心原则，优先级从高到低：

1. **今天能完成** > 内容丰富。任务必须在5分钟内完成，失败体验会快速摧毁习惯。
2. **降低摩擦** > 制造代价。对6-8岁用户，减少决策点比设计惩罚机制更有效。
3. **即时反馈** > 延迟奖励。6-8岁孩子无法感知延迟满足，完成瞬间必须有反馈。
4. **积累可见** > 数字堆积。用诗集、日期戳等实物感设计，让孩子看到时间维度。
5. **简单先行** > 完美一步到位。第一版验证框架，算法迭代放后续。

## 三、功能需求

### 3.1 首页重设计（P0）

**当前状态**：诗词列表，用户自主选择  
**目标状态**：以今日任务为主体，一键开始

#### 3.1.1 今日任务卡片

- 占首屏主体区域（建议60%以上高度）
- 卡片内容：
  - 诗名（大字，主标题）
  - 诗的第一句（副标题）
  - 诗词背景介绍（≤15字，激活情感连接，例："李白写的，想念故乡的夜晚"）
  - 意境背景色 + 意象 emoji（每首诗配置一组，JSON维护）
  - "开始背诗"主按钮

#### 3.1.2 今日状态视觉区分

| 状态 | 视觉表现 |
|------|---------|
| 未完成 | 卡片橙色边框/提示色，按钮醒目 |
| 已完成 | 卡片绿色，显示"今天完成了！"，按钮变为"再背一遍" |

#### 3.1.3 连续天数

- 位置：首屏右上角
- 样式：数字足够大，文案"已连续 N 天"
- 补签机会：紧跟连续天数下方，"本周还有 N 次补签"（小图标）

#### 3.1.4 第二屏入口

- 诗集（历史归档）
- 探索更多（原诗词库）
- 不占首屏，降级处理

---

### 3.2 每日推荐逻辑（P0）

#### 3.2.1 第一版：固定顺序

- 推荐逻辑：localStorage 存 `dayIndex`，每日 +1，对应诗库数组
- 前7首：高全国知名度 + 最简单，固定为：
  1. 静夜思（李白）
  2. 咏鹅（骆宾王）
  3. 春晓（孟浩然）
  4. 锄禾（李绅）
  5. 登鹳雀楼（王之涣）
  6. 相思（王维）
  7. 江南（汉乐府）
- 第8首起：按难度爬坡排序的诗库，排序由陈博士提供（音节数 + 常用字占比 + 知名度三维度）
- 诗库跑完后循环（进入"复习模式"）

#### 3.2.2 后续迭代：难度分桶动态推荐（P2，不在第一版）

- 按音节数和常用字占比将诗分为简单/中等/稍难三个桶
- 根据孩子完成率动态升降桶
- 连续3天三关全过 → 升桶；连续2天卡第一关 → 降桶

---

### 3.3 连续打卡与补签机制（P1）

#### 3.3.1 连续天数逻辑

- 每日完成任务（背完当天推荐诗）→ 连续天数 +1
- 断一天 → 连续天数不立即清零，进入"可补签"状态
- 断两天及以上 → 连续链断开，但显示"最长连续 X 天"作为历史锚点

#### 3.3.2 补签机制

- 每自然周（周一重置）提供 1 次免费补签机会
- 用法：断了一天，次日完成当天任务 → 自动续接连续天数，消耗1次补签
- 不增加额外任务量（补签门槛 = 完成今日1首，与正常天相同）
- 补签机会用图标显示剩余次数，制造机会稀缺感
- localStorage 存储：`{ week: N, usedChance: 0|1 }`

#### 3.3.3 数据丢失容灾

- 每周完成后生成可截图分享的"本周诗集"页面
- 让孩子有情感锚点存在相册，不完全依赖 localStorage

---

### 3.4 完成后反馈流程（P0 + P1）

完成背诗后，按以下顺序呈现：

```
第一步（P0，已有）：撒花动画 + 音效
         ↓
第二步（P1）：诗集归档提示——"《静夜思》已加入你的诗集，第8首"
         ↓
第三步（P1）：明日诗预告——"明天会背：'春眠不觉晓……'"
         ↓
第四步（P1）：展示完整诗文 + "背给家长听"文字提示
         ↓
（可选，P2，后续迭代）：录音功能入口
```

#### 关键约束

- "背给家长听"必须是**可选出口**，不是必经流程
- 录音功能第一版不做，避免增加孩子心理压力

---

### 3.5 诗集视图（P1）

- 入口：首页第二屏
- 每首已背诗显示：诗名、作者、完成日期
- 设计风格：实体书翻页感，让孩子感受时间积累
- 点击可查看全文和背景介绍

---

### 3.6 诗词配置数据（P0）

每首诗的 JSON 配置需包含以下字段：

```json
{
  "id": "jing-ye-si",
  "title": "静夜思",
  "author": "李白",
  "dynasty": "唐",
  "lines": ["床前明月光", "疑是地上霜", "举头望明月", "低头思故乡"],
  "intro": "李白写的，想念故乡的夜晚",
  "themeColor": "#1a2a4a",
  "emoji": "🌕",
  "difficulty": 1,
  "syllableCount": 20,
  "commonCharRatio": 0.95
}
```

## 四、非功能需求

### 技术约束

- 纯前端，无后端
- 所有状态存 localStorage（dayIndex、streak、weekChance、completedPoems）
- 换设备数据会丢失，属于已知局限，通过截图/分享降低情感损失

### 性能要求

- 首页加载 < 1秒
- 撒花动画流畅，不卡顿（6-8岁孩子对卡顿容忍度极低）

### 兼容性

- 移动端优先
- iOS Safari / Android Chrome

---

## 五、不做的事（第一版明确排除）

| 功能 | 排除原因 |
|------|---------|
| 录音分享 | 开发成本高，可用文字提示替代核心需求 |
| 动态难度分桶 | 需要给所有诗打标签+维护完成率逻辑，延后迭代 |
| 后端账号系统 | 超出当前技术架构范围 |
| 家长管理后台 | 超出范围 |
| AI 评分/跟读 | 超出范围 |
| 年级标签/手动分级 | 用自适应桶机制替代，第二版实现 |

## 六、成功指标

| 指标 | 目标 | 测量方式 |
|------|------|---------|
| 次日留存率 | > 40% | localStorage 事件统计 |
| 第7天留存率 | > 20% | localStorage 事件统计 |
| 单次任务完成率 | > 80% | 开始背诗 → 完成三关的转化 |
| 平均连续天数 | > 5天 | localStorage 统计 |
