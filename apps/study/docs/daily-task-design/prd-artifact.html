01背景与目标

核心问题：当前产品像字典——用完即走。用户进来背一首诗，背完之后没有任何东西在等他们回来。

根因诊断（五角色一致认同）

没有"今天该做什么"的明确锚点，首页是开放式内容库而非任务驱动界面
完成之后没有召回钩子，不回来没有任何损失
进度数字"已背 X 首"对 6-8 岁孩子没有情绪意义，数字不等于动力
缺少完成感的积累——字典是查完即走的工具，没有时间维度

量化目标

指标现状（估算）v1 目标
次日留存率< 15%> 40%
7 日留存率< 5%> 20%
当日打开后任务完成率—> 60%
坚持 7 天以上用户占比—> 15%

设计原则（全员共识）

任务要小，要必定完成：每天一首，5 分钟内完成，不能让孩子有失败体验
即时可见的成就积累：完成瞬间要有视觉 + 听觉爆发，延迟满足对 6-8 岁无效
不惩罚，不归零：断掉不清空，用温暖语言召回，不能给孩子和家长制造焦虑
奖励服务于学习本身：撒花、连续天数是"我又背了一首诗"的放大器，不能反客为主

02用户故事

主要用户：6-8 岁孩子

US-01
作为一个 6 岁的孩子，我希望打开 app 就能看到今天要背哪首诗，以便不需要自己想或者问家长，直接开始就好。
US-02
作为一个正在背诗的孩子，我希望背完诗的那一刻有撒花和音效，以便感受到"我做到了"的成就感。
US-03
作为一个连续背了几天诗的孩子，我希望看到"已坚持 X 天"的数字每天长大，以便有继续回来的动力。
US-04
作为一个昨天没背诗的孩子，我希望今天打开 app 时看到温暖的欢迎提示而不是惩罚，以便不会因为"断了"就彻底放弃。
US-05
作为一个刚背完诗的孩子，我希望能看到整首诗的全文，以便叫家长来听我背一遍。

次要用户：家长

US-06
作为一个家长，我希望只需一次性设置孩子的年级，以便之后系统自动推荐合适的诗，不需要我每天操心。
US-07
作为一个家长，我希望首页今日任务够显眼、够明确，以便孩子自己打开 app 就知道该做什么，我不需要全程陪同。
US-08
作为一个家长，我希望孩子背完后有"已完成"的视觉状态，以便偶尔瞥一眼就知道孩子今天做了没有。

3.3 今日推荐逻辑

function getTodayPoem(grade) {
  const poemList = POEM_LIST[grade];        // 按难度排序的诗目数组
  const startDate = storage.get('daily_task.start_date');
  const today     = getTodayStr();          // "YYYY-MM-DD"
  const dayIndex  = diffDays(startDate, today);  // 今天是第几天（从0开始）
  const idx       = dayIndex % poemList.length;  // 跑完后复习循环
  return poemList[idx];
}
规则：每天自动推进一首，以 start_date 为 Day 0。当天完成或未完成，第二天均推进到下一首（不补昨天的诗）。年级切换后 start_date 重置，从新年级第一首重新推进。

3.4 Streak（坚持天数）机制

function updateStreak() {
  const data  = loadDailyTask();
  const today = getTodayStr();
  if (data.last_complete_date === today) return; // 当天已计算，跳过
  data.streak_count += 1;
  data.last_complete_date = today;
  data.today_complete = true;
  saveDailyTask(data);
}
情况展示文案
streak_count === 0今天开始第一天！
streak_count > 0已坚持 N 天
不做：不清零、不归零、不显示"连续天数已中断"等惩罚性文案。v1 统一用累计天数，文案用"已坚持"而非"连续"。

04数据结构设计

所有数据存储于 localStorage，key 为 poem_app_data，value 为 JSON 字符串。

完整结构

{
  "daily_task": {
    "grade": 1,                         // 年级，1 或 2；未设置为 null
    "start_date": "2026-10-01",         // 首次使用日期，计算 dayIndex 用
    "streak_count": 12,                 // 累计坚持天数，只增不减
    "last_complete_date": "2026-10-07", // 最后完成日期，判断今日是否已完成
    "today_complete": false             // 当日完成状态，跨日后自动重置
  },
  "poem_progress": {
    "jing-ye-si": {
      "read": true,
      "memorized": true,
      "memorized_date": "2026-10-01"
    }
  }
}

字段说明

字段类型说明
gradenumber | null年级，1 或 2；未设置为 null
start_datestring"YYYY-MM-DD"；用于计算今日推荐序号
streak_countnumber累计坚持天数，只增不减，初始为 0
last_complete_datestring | null最后完成任务日期；用于判断今日是否已完成
today_completeboolean当日完成状态；日期变化时自动重置为 false
poem_progress[key]objectkey 为诗的拼音 slug，如 "jing-ye-si"

初始化逻辑

function loadDailyTask() {
  try {
    const raw = localStorage.getItem('poem_app_data');
    if (!raw) return getDefaultData();
    const data = JSON.parse(raw);
    // 跨日重置 today_complete（注意：streak_count 不变）
    if (data.daily_task.last_complete_date !== getTodayStr()) {
      data.daily_task.today_complete = false;
    }
    return data;
  } catch (e) {
    return getDefaultData(); // JSON 解析失败时重新初始化
  }
}

function saveDailyTask(data) {
  try {
    localStorage.setItem('poem_app_data', JSON.stringify(data));
  } catch (e) {
    console.warn('localStorage write failed', e); // 私人浏览模式下静默降级
  }
}
已知局限（v1 接受的技术债）：换设备或清除浏览器缓存后，所有进度丢失，从头开始。解决需账号体系，v1 不处理。建议在首次使用引导时展示一行小字："建议固定在同一台设备使用"。

05通知策略

v1 结论：不做推送通知。iOS Safari 对 PWA 通知的真实用户授权率低于 20%，把留存押注在大多数用户会拒绝的权限上是设计失败（老李 + 王妈妈联合判断，张总裁定）。

v1 降级方案

用首屏显眼性替代推送——即"打开就是正确的行为提示"：

今日任务卡片占首屏 55-60%，进入 app 第一眼就是今日任务
完成第一次任务后，展示静态文字引导：
"小贴士：每天固定时间背一首，效果最好！可以在手机时钟里设一个每天的小提醒"

v2 规划（有数据后决策）

项目规格
授权触发时机孩子完成第一次任务后，先体验到价值再引导
控制权家长可设置推送时间段（如每天 18:00-19:00）
默认关闭，不主动请求权限
授权文案"要不要每天提醒来背诗？"

06验收标准

AC-01：首页今日任务卡片显示

打开 app，首屏可见今日任务卡片（不需要滚动）
卡片展示今日推荐诗的诗名、作者、15 字背景介绍
卡片底部显示"已坚持 N 天"，N 为正确的累计完成天数
grade 未设置时，卡片区域显示年级选择引导，不显示任务卡片

AC-02：今日任务完成流程

点击"开始今天的诗"直接进入背一背模式，不经过详情页
背一背三关全部完成后，触发撒花动画
撒花后展示完整诗文 + "背给家长听"提示文字
点击"回首页"后，首页卡片切换为状态 B（已完成）
状态 B：卡片边框变绿，按钮变为"今天已完成"不可点击
状态 B：streak 数字显示新值，有 +1 标记和弹跳动画

AC-03：Streak 数据正确性

首次完成任务：streak_count 从 0 变为 1
连续完成第 N 天：streak_count 正确递增
昨天未完成，今天完成：streak_count 仍然正确递增（不归零）
同一天第二次完成背一背：streak_count 不重复计数
次日打开 app：today_complete 自动重置为 false，streak_count 不变

AC-04：久违回访提示

最后完成日期不是昨天也不是今天，进入首页时显示"好久不见，继续出发！"横幅
横幅 4 秒后自动消失
横幅不遮挡今日任务卡片的主要内容
连续完成中回来，不显示此横幅

AC-05：年级设置

顶栏设置图标可点击，弹出年级选择面板
选择年级并确认后，今日推荐诗切换为新年级第一首
点击遮罩层关闭面板，年级不变
年级切换后 start_date 重置，day_index 从 0 重算

AC-06：今日推荐逻辑

第一次使用推荐第一首诗（静夜思）
第二天打开推荐第二首诗（咏鹅）
今天完成或未完成，第二天均推进到下一首
跑完全部诗目后从第一首重新开始（循环）

AC-07：降级处理

localStorage 读取失败（如私人浏览模式）：app 正常显示，使用默认值，不崩溃
localStorage 写入失败：app 正常运行，静默失败，不弹错误提示
数据结构损坏（JSON 解析失败）：使用默认值重新初始化，不崩溃

07不做什么（Out of Scope）

功能排除原因计划
家长每日手选今日诗制造决策疲劳，v1 先验证固定推荐框架v2 待数据决策
补做昨日未完成内容增加复杂度，且制造"欠债感"，与设计原则冲突不做
补签机制（每周1次）v1 以简单性为优先，先验证核心框架v1.1
诗集归档视图需要额外页面开发，v1 先跑通核心任务流程v1.1
明日诗预告待视觉稿确认后迭代v1.1
PWA 推送通知iOS 授权率低，不适合 v1 押注v2
录音分享功能技术成本高，文字提示已覆盖核心需求v2
动态难度分桶推荐需全量打标签 + 维护完成率，需先有数据v3+
账号体系 / 跨设备同步需后端，超出当前纯前端架构v3+
