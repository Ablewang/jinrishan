# 第六轮：全员收口——五人最终共识会议

> **目标**：整合前五轮辩论结论，对仍有分歧的点做最终裁定，形成可以写进需求文档的共识。
>
> 参与角色：陈博士、张总、小林、王妈妈、老李（全员）

---

**张总（主持）：**

我来梳理一下目前的共识和未解决的分歧。

已共识的部分：
- 首页改成"今日任务"为主体，不再是诗词列表
- 前7首固定为高知名度诗，之后按顺序或难度桶推进
- 连续天数显示在首屏，每周一次免费补签
- 完成后：撒花（已有）→ 诗集归档 → 明日诗预告 → 可选录音分享
- 视觉差异化用颜色+意象 emoji，低成本先跑通

还有两个点没有最终裁定：

**分歧一**：第一版推荐逻辑，纯固定顺序（老李主张）还是难度分桶随机（小林主张）？

**分歧二**：录音分享功能，第一版就做，还是放后续迭代？

---

**老李：**

分歧一我坚持：第一版纯固定顺序。原因是技术风险控制——难度分桶需要给每首诗打标签、维护完成率、实现升降桶逻辑，这是 3-4 天的工作量。固定顺序是 2 小时。第一版的目标是验证"每日任务这个框架本身有没有提升留存"，不是验证算法。算法好坏要等框架跑起来有数据再判断。

**小林：**

我接受老李的判断。但有一个条件：固定顺序的前20首必须经过人工审核，保证难度是爬坡的——不能按我们原来诗库的随机顺序排。谁来排这个序？

**陈博士：**

我来。按我说的两个维度：音节数和常用字占比，再加上"全国知名度"这个感性因素——知名度高的诗孩子有可能在幼儿园听过，上手更快。我给出一个排序建议，张总来最终确认。

**张总：**

好，陈博士出排序，我确认。这条线关闭。

分歧二——录音功能。王妈妈，你是最强烈的倡导者，但老李说实现成本不低，你的优先级判断？

**王妈妈：**

我退一步。录音不做没关系，但至少给孩子一个"展示"的出口。哪怕最简单的——背完之后屏幕上出现这首诗的全文，下面有一个"背给家长听"的提示，让孩子主动叫家长来听。这个不需要开发，就是一个静态文字提示，成本零。录音功能放后续。

**小林：**

王妈妈这个方案很聪明。"背给家长听"这五个字把孩子推向现实中的社交验证，比 app 内任何功能都强。我支持。

**老李：**

完全同意，这个我5分钟能加进去。

**陈博士（最后补一条）：**

有一个细节我一直没提，现在说。孩子每天进来，今日任务卡片上除了诗名，建议加一句**非常短的背景介绍**——不超过15个字，比如"李白写的，想念故乡的夜晚"。这不是注释，是激活孩子的情感接收。没有情感连接的诗，背了也只是声音，不会在记忆里留下来。这条成本极低，每首诗一句话，我也可以写。

**张总：**

好，这条加进去。我来整理完整的结论，送给老李实现。

---

## 最终共识（五人全员确认）

### 核心框架

**每日任务系统**是 app 的主轴，从"内容库"模式切换到"每日任务"模式。

### 功能清单（第一版）

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 首页今日任务卡片 | 占主屏，诗名+第一句+意境色+意象emoji+15字背景介绍 | P0 |
| 今日状态指示 | 未完成橙/已完成绿，视觉区分 | P0 |
| 连续天数显示 | 首屏右上角，数字大 | P0 |
| 固定顺序推荐 | 前7首高知名度，20首经过难度排序，localStorage存dayIndex | P0 |
| 完成后诗集归档 | 带完成日期戳，可翻阅 | P1 |
| 明日诗预告 | 撒花结束后展示明日诗第一句 | P1 |
| 补签机制 | 每周1次，断一天次日完成自动续接 | P1 |
| "背给家长听"提示 | 完成后静态文字出口 | P1 |
| 录音分享 | 放后续迭代 | P2 |
| 动态难度分桶推荐 | 放后续迭代 | P2 |

### 分歧最终裁定

- 推荐逻辑第一版：**固定顺序**，由陈博士提供排序，张总审核
- 录音功能：**第一版不做**，用"背给家长听"文字提示替代
- 诗词背景介绍：**做，每首15字以内**，由陈博士撰写文案
