# 每日任务系统 · 产品需求文档

**版本**：v1.0  
**日期**：2026-10-08  
**负责人**：张总（PM）  
**讨论参与**：陈博士（儿童心理学）、小林（游戏设计）、王妈妈（家长代表）、老李（前端）

## 一、背景与问题

当前产品的核心问题：**像字典，用完即走**。

根因诊断：
- 没有"今天该做什么"的明确锚点
- 用完之后没有任何召回钩子
- 进度数字（已背 X 首）对 6-8 岁孩子没有情绪意义
- 首页是开放式内容库，而非任务驱动界面

6-8 岁儿童的习惯养成依赖**外部结构**，而非内在动机。每日任务系统的核心目标是为孩子提供这个外部结构，让每次进入 app 有明确目标，做完有成就感，第二天有理由回来。

---

## 二、目标用户

| 用户 | 使用场景 | 核心诉求 |
|------|----------|----------|
| 6-8 岁孩子 | 每天独立使用，5 分钟内完成 | 知道今天做什么，做完有成就感 |
| 家长 | 一次性设置年级，偶尔查看完成状态 | 不需要每天操心"今天背哪首"，能看到孩子做了没有 |

---

## 三、功能需求

### 3.1 今日任务推荐

**逻辑规则：**
- 家长首次使用时选择年级（一年级 / 二年级）
- 系统按该年级诗目顺序，每天自动推进一首
- 计算基准：以设备首次使用日期为 Day 0，当前日期 - Day 0 = 今日推荐序号
- 当天完成或未完成，第二天均推进到下一首（不补昨天的诗）
- 年级切换后，从新年级第一首重新开始，旧年级进度保留但不继续推进

**边界说明：**
- v1 不支持家长每日手选（留 v2）
- v1 不支持智能推荐（留 v2）
- v1 不支持补做昨日未完成内容

**诗目顺序要求：**
- 需语文老师审核各年级推荐顺序，不能纯靠课标顺序排列
- 前三首的选诗标准：孩子熟悉但未必背过、难度低、节奏感强
- 此项为上线前前置条件，PM 负责协调

---

### 3.2 今日任务卡片（首页新增模块）

今日任务卡片插入首页顶部，位于顶栏下方，诗词列表上方。

#### 状态 A：今日任务未完成

```
┌─────────────────────────────────────────┐
│  [角色形象]  小诗人，今天来背一首！       │
│             《静夜思》· 唐·李白          │
│                                         │
│         [ 开始今天的诗 → ]              │
│                                         │
│  🕯 已坚持 12 天                        │
└─────────────────────────────────────────┘
```

**元素说明：**
- 角色形象：占位为毛笔小人或诗人卡通形象，v1 可用简单图标，视觉稿阶段确定
- 邀请文案：固定格式"小诗人，今天来背一首！"（可在后续版本根据连续天数变化）
- 诗名+作者：使用 Ma Shan Zheng 字体，大字展示
- 开始按钮：朱砂红大按钮，圆角胶囊形，点击进入该诗的背一背模式
- 已坚持天数：小图标 + 数字，放卡片底部左侧

#### 状态 B：今日任务已完成

```
┌─────────────────────────────────────────┐
│  [角色形象+庆祝状态]  太棒了！           │
│             《静夜思》今天背完啦！       │
│                                         │
│         ✓ 今天已完成，明天继续          │
│                                         │
│  🕯 已坚持 13 天  ↑ +1                 │
└─────────────────────────────────────────┘
```

**元素说明：**
- 角色形象变为庆祝姿态（举手/发光/笑脸）
- 已坚持天数显示更新后的数字，旁边有"+1"小标记（数字跳动动画）
- 开始按钮替换为灰色"今天已完成"状态文字，不可点击（避免孩子疑惑是否做完）

#### 状态 C：昨日未完成，今日回访

首次进入时，卡片顶部出现一行温暖提示小字：

> "好久不见，继续出发！"

提示出现后 3 秒自动消失，或用户点击任意处消失。不弹窗，不打断流程。

---

### 3.3 Streak（坚持天数）机制

**计算规则：**
- 今日任务完成：坚持天数 +1
- 今日未完成：坚持天数不变（非归零）
- 连续断了 N 天后回来：首页显示状态 C 的温暖提示，坚持天数继续从上次数字累加

**展示逻辑：**

| 情况 | 展示文案 |
|------|----------|
| 连续完成中 | "已坚持 X 天" |
| 本月累计（可选，v1 暂不做）| "本月完成 X 天" |
| 刚开始（第 0 天）| 不显示天数，显示"今天开始第一天！" |

**设计原则：**
- 不显示"连续天数已中断"等惩罚性文案
- 不归零，不清空
- 数字更新时有跳动动画（CSS，从 N→N+1 翻滚效果）

---

### 3.4 年级设置

**入口：** 首页顶栏右侧的"设置"图标（或首次使用时引导弹窗）

**操作流程：**
1. 用户点击设置
2. 看到年级选择：一年级 / 二年级
3. 选择后确认，系统更新今日推荐诗目
4. 可随时回来修改

**首次使用引导（可选，v1 简化版）：**
- 第一次打开 app，首页任务卡片区域显示"先告诉我你在几年级？"
- 两个按钮：一年级 / 二年级
- 选择后直接进入正常首页，不需要其他引导步骤

## 四、首页改版规范

### 改版前（现状）

```
顶栏

诗词卡片列表（主内容）
```

### 改版后

```
顶栏
```

**改版原则：**

- 原有诗词列表保留，但视觉权重降低
- 进度条（已背 X/70）迁移至任务卡片内或精简为小文字，不再占首屏显眼位置

## 五、交互细节

| 场景 | 交互 |
|------|------|
| 点击"开始今天的诗"按钮 | 直接进入该诗的背一背模式（跳过详情页，或先进详情页再进背一背，待定） |
| 背一背完成后 | 触发撒花动画（已有），动画结束后自动标记今日任务完成，跳转回首页，首页展示状态 B |
| 状态 B 时点击今日任务卡片区域 | 进入该诗详情页（允许重复阅读，但不重置完成状态） |
| 换了新诗之后，旧任务卡入口 | 旧诗仍可在列表中找到，卡片上有"已背"绿色勾标记 |

**待定项：**
- 点击"开始"后是否先进详情页再进背一背，还是直接进背一背？建议：直接进背一背，减少跳转层级，第一次背该诗时可在背一背界面顶部展示完整诗文供参考。

## 六、数据存储（localStorage）

在现有 `poem_progress` 基础上，新增以下字段：

```json
{
  "daily_task": {
    "grade": 1,
    "start_date": "2026-10-01",
    "streak_count": 12,
    "last_complete_date": "2026-10-07",
    "today_complete": false
  },
  "poem_progress": {
    "1": { "read": true, "memorized": true },
    ...
  }
}
```

**字段说明：**
- `grade`：年级，1 或 2
- `start_date`：首次使用日期，用于计算今日推荐序号
- `streak_count`：累计坚持天数（只增不减）
- `last_complete_date`：最后一次完成任务的日期（用于判断今日是否已完成）
- `today_complete`：当日完成状态（跨日后自动重置）

**风险说明（v1 已知局限）：**
- 换设备或清除浏览器缓存后，所有进度丢失，从头开始
- 该问题需账号体系才能根本解决，v1 不处理
- 建议在首次使用引导时告知用户"建议固定在同一台设备使用"

## 七、不做（v1 明确排除）

| 功能 | 排除原因 | 计划版本 |
|------|----------|----------|
| 家长每日手选今日诗 | 增加决策疲劳，v1 先验证固定推荐留存效果 | v2 |
| 智能推荐算法 | 需要行为数据积累，v1 无后端 | v3+ |
| 补做昨日未完成内容 | 增加系统复杂度，且会给孩子造成"欠债感" | 不做 |
| 推送通知 | 依赖 PWA 授权，用户接受度不稳定，v1 降级为首页横幅提示 | v2 |
| 账号体系 / 跨设备同步 | 需后端，v1 纯前端 | v3+ |
| 家长查看报告 / 进度分享 | 单独功能，v2 做完成分享图 | v2 |

## 八、成功指标

| 指标 | v1 目标 | 测量方式 |
|------|---------|----------|
| 次日留存率 | > 40%（现状估算 < 15%） | 设备本地无法直接测量，需灰度发布后用渠道数据估算 |
| 7 日留存率 | > 20% | 同上 |
| 任务完成率（当日打开后完成） | > 60% | localStorage 事件统计（如接入埋点） |
| 坚持 7 天以上用户占比 | > 15% | streak_count 分布 |
