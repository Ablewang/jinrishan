# 第五轮：辩论——首页应该长什么样？今日任务如何呈现？

> **辩题**：首页是整个 app 的"门脸"，也是孩子每天第一眼看到的地方。当前首页是诗词列表，应该改成什么？今日任务的视觉优先级应该有多高？
>
> 参与角色：张总、小林、老李

---

**张总：**

首页现在是内容库入口，这是字典思维的具体体现。必须改。新首页的第一屏只做一件事：**告诉孩子今天要背哪首，以及他今天有没有做**。其他所有内容——历史诗集、探索更多——降到第二屏或 tab。视觉上，今日任务卡片要占首屏 60% 以上的面积，字大、色鲜、按钮明显。连续天数显示在右上角，数字要足够大，让孩子一眼看到"我已经连续12天了"。首页的设计目标只有一个：**进来3秒内知道今天要做什么，一个按钮开始**。

**小林：**

张总说的方向完全正确，但我要补游戏设计的角度：**首页必须有"状态变化"**。如果首页每天长得一模一样，孩子很快就不觉得它是个"活的"东西。Duolingo 的首页每天有不同的角色表情、不同的鼓励话语——内容变化制造"今天不一样"的感知。我建议：今日任务卡片的背景插图跟诗的意境匹配——背《静夜思》时是月亮，背《咏鹅》时是鹅在水里。不需要动画，静态插图就够，但让每天的视觉体验是新的。孩子打开看到图就知道"今天是什么诗"，图本身就是任务的预告。

**老李：**

你们两个描述的方向我支持，但要谈实现代价。张总说的"今日任务卡片占60%面积"，我问一个问题：这首诗是谁决定的？如果是算法根据难度桶随机抽的，那我今天就要实现这套逻辑，包括桶的建立、完成率跟踪、升降桶逻辑——这不是一个 UI 改版，是一个完整的推荐系统。我建议分两步走：**第一版首页改版先用"固定顺序"**——按预设的顺序，第N天就推第N首，不做动态推荐。UI 先做对，推荐算法后迭代。小林说的意境插图我支持，但插图要提前准备好资源，每首诗一张，如果诗库有100首就要100张图，这是内容工作量不是开发工作量，需要提前规划。

**张总（回应老李）：**

老李分两步走的思路务实，我接受。但有一个地方不能妥协：**首页改版和任务逻辑必须同步上线**，不能先改首页但还是让孩子自己选诗——那只是换了个皮，解决不了"像字典"的根本问题。哪怕第一版是完全固定顺序、不动态推荐，首页也必须展示"今天要背这首"而不是"这里有所有诗你来选"。固定顺序的推荐逻辑其实非常简单，localStorage 存一个 dayIndex，每天加1，对应诗库数组，老李半天能搞定。

**小林（回应老李）：**

意境插图的工作量问题，我有个低成本方案：不需要100张定制插图，用**诗词里的核心意象关键词**对应一批通用背景色+一个大号 emoji 表意——《静夜思》是深蓝色背景+🌕，《咏鹅》是浅绿色背景+鹅的剪影。不需要设计资源，代码里维护一个诗→颜色+意象的映射表，视觉上已经比纯色卡片丰富很多。后续有设计资源了再换成真插图，不影响架构。

**老李：**

小林这个方案可以，颜色+意象映射表我来维护，JSON 配置，和诗库数据放一起。这个方案开发成本低，视觉差异化够用，先这样。

---

## 倾向性结论（老李代表本组）

**首页重设计方案（第一版可落地）：**

1. **首屏只做一件事**：今日任务卡片占屏幕主体，展示今天要背的诗名+第一句，一个大按钮"开始背诗"。

2. **今日状态一眼可见**：
   - 未完成：卡片橙色边框，按钮醒目
   - 已完成：卡片变绿，显示"今天完成了！"

3. **连续天数显示**：右上角大数字，"已连续 N 天"，旁边显示本周补签机会。

4. **视觉差异化（低成本方案）**：每首诗对应一个背景色+意象 emoji，JSON 配置维护，后续可升级为插图。

5. **推荐逻辑第一版**：固定顺序，dayIndex 存 localStorage，每天推对应诗，前7首为高知名度简单诗。动态推荐作为后续迭代。

6. **第二屏**：历史诗集入口 + 探索更多，不占首屏注意力。
