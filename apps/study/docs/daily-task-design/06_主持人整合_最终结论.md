# 主持人整合：每日任务系统最终结论

**日期**：2026-10-08  
**主持人**：张总（代表整合视角）  
**基于**：五位角色、四组辩题、六轮深度讨论

---

## 一、核心共识（全员一致）

**1. 首页从"内容库"切换到"今日任务"**  
app 的根本问题不是内容不够，是没有每日驱动力。首页主体必须是今日任务卡片，诗词列表降级为次要入口。

**2. 任务必须"今天能完成"，不给孩子和家长任何选择**  
系统自动推荐每日一首，5分钟内可完成。决策疲劳是留存杀手，固定推荐比自定义对6-8岁用户更友好。

**3. 完成瞬间的即时反馈是驱动力核心**  
撒花动画已经是正确方向。连续天数、积分、徽章都是辅助，不能反客为主。孩子来是为了背诗的成就感，不是为了收集奖励。

**4. Streak 要做，但做"温柔版"：不归零、不惩罚**  
显示"已坚持 X 天"，断掉后改为"本月完成 X 天"，用温暖语言而非清零惩罚。断掉后首次回访显示"好久不见，继续出发！"。

**5. 第一版验证框架，算法迭代放后续**  
推荐逻辑用固定顺序，前20首人工排序保证难度爬坡。先跑起来有数据，再考虑动态难度分桶。

## 二、遗留分歧

### 分歧一：Streak 展示位置

| 角色 | 立场 |
|------|------|
| 小林 | 必须在首屏醒目位置，损失规避的前提是孩子每次进来都能看到 |
| 陈博士 | 应该次要展示，不能是首屏最大视觉元素，避免变成焦虑源 |
| 王妈妈 | 反对"今天必须打卡"的压迫感，认同小林的可见性但不接受显眼程度 |

### 分歧二：第一版推荐逻辑

| 角色 | 立场 |
|------|------|
| 老李 | 纯固定顺序，2小时实现，第一版只验证框架 |
| 小林 | 难度分桶随机，提供新鲜感，避免重复疲劳 |
| 陈博士 | 支持有顺序，但顺序要经过设计，不能是随机 |

### 分歧三：PWA 通知

| 角色 | 立场 |
|------|------|
| 张总 | 通知是任务系统的触发器，没有召回就是死系统，是核心功能 |
| 老李 | iOS 授权率不到20%，不能把核心体验押注在一个大多数人拒绝的权限上 |
| 王妈妈 | 通知要做但要家长控制时间段，烦了家长会先关掉 |

## 三、设计决策

### 决策一：Streak 放卡片内部，不单独占一行

**理由**：小林的"可见"和陈博士的"次要"可以用位置而非大小来调和。Streak 显示在今日任务卡片内部（卡片右上角或底部），与任务信息共生——孩子每次进来开始任务前自然看到，但不是进入首屏的第一视觉焦点。王妈妈的顾虑（"今天必须打卡"的压力感）来自于 streak 独占视觉权重，放在卡片内后问题消解。

具体实现：未完成状态显示"已坚持 N 天 🌟"（小字），完成瞬间数字从 N 跳到 N+1（CSS 翻滚动画）。

### 决策二：第一版固定顺序，但前20首必须人工排序

**理由**：老李的工程判断是对的——第一版的目标是验证"每日任务框架有没有提升留存"，不是验证推荐算法。固定顺序省出的3天开发时间，可以用来打磨完成后的反馈流程（诗集归档、明日预告），对留存的影响更直接。但小林的"新鲜感"担忧不能无视——缓解方案是保证前20首难度确实爬坡、内容有变化，让孩子背到第10首时还有兴趣，而不是靠随机性维持。

陈博士负责提供排序（音节数 + 常用字占比 + 全国知名度三维度），张总审核后写入配置。

### 决策三：通知第一版不做，但设计上为它留位置

**理由**：老李的 iOS 现实数据不能忽略。iOS Safari 的 PWA 通知支持到最近才松口，真实授权率低，把留存押注在一个大部分用户会拒绝的权限上，是设计失败。但张总的逻辑也成立——没有召回机制，纯靠"首屏好看"是不够的。

折中方案：第一版不做推送，但在孩子**完成第一次任务后**引导家长手动设置手机提醒（系统日历/时钟），同时首屏的今日任务卡片要足够显眼，让每次打开就是正确的行为提示。第二版上 PWA 通知，且引导授权放在完成体验之后——先让孩子尝到甜头，再问要不要提醒。

## 四、每日任务系统功能清单

### P0（上线前必须完成）

- **[P0] 首页今日任务卡片**：占首屏主体（约60%），两态：未完成（邀请文案+开始按钮）/ 已完成（庆祝状态+明日见）
- **[P0] 今日推荐逻辑**：localStorage 存 dayIndex，固定顺序每日推进一首，跑完后进入复习循环
- **[P0] 前7首固定高知名度诗**：静夜思→咏鹅→春晓→锄禾→登鹳雀楼→相思→江南，保证新用户第一周100%能完成
- **[P0] 诗词背景介绍**：每首15字以内，激活情感连接，例："李白写的，想念故乡的夜晚"
- **[P0] 卡片邀请文案**：不是通知语气，是邀请语气，例："小诗人，李白在等你！"
- **[P0] 温柔 Streak 显示**：卡片内"已坚持 N 天"，断掉改"本月完成 N 天"，不归零
- **[P0] Streak 数字跳动动画**：完成瞬间 CSS 翻滚从 N 到 N+1
- **[P0] 断掉回访温暖提示**：首次回访卡片顶出现"好久不见，继续出发！"小横条，4秒消失
- **[P0] 完成后撒花动画**：现有功能保留，这是即时反馈的核心

### P1（第一版迭代，上线后1-2周）

- **[P1] 诗集归档视图**：历史已背诗+完成日期，实体书翻页风格，让孩子看到时间积累
- **[P1] 明日诗预告**：撒花结束后展示明日诗第一句，制造期待感
- **[P1] "背给家长听"文字提示**：完成后展示完整诗文+静态提示，零开发成本，强社交验证
- **[P1] 年级设置**：设置入口一次性选择（一年级/二年级），年级切换后从新年级第一首重新推进
- **[P1] 补签机制**：每自然周1次免费补签，断一天次日完成自动续接，图标显示剩余次数

### P2（后续版本，有数据再决策）

- **[P2] 动态难度分桶推荐**：按音节数+常用字占比分简单/中等/稍难三桶，根据完成率升降桶，需要给所有诗打标签
- **[P2] PWA 推送通知**：家长设置时间段，授权引导放在孩子完成第一次任务之后
- **[P2] 录音分享功能**：孩子录音背诗并分享，技术成本高，先用"背给家长听"文字提示覆盖核心需求
- **[P2] 家长每日手选**：高需求密度但低频使用，等第一版留存数据出来再判断是否值得做

## 六、不做的事（v1 明确排除，不再讨论）

| 功能 | 排除理由 |
|------|---------|
| 家长每日手选 | 决策疲劳，v1 验证框架，v2 用数据决策 |
| 推送通知 | iOS 授权率低，押注在此是设计失败，v2 做 |
| 录音分享 | 文字提示已覆盖核心需求，节省开发成本 |
| 动态难度算法 | 需打全量标签+维护完成率，3-4天工作量，延后 |
| 补昨天未完成的诗 | 增加复杂度，不背昨天也不影响今天，简化为"今天推新一首" |
| 账号体系/跨设备同步 | 超出当前技术架构，localStorage 是已知局限 |
| 年级标签强制引导 | 不阻断体验，设置可选，系统靠完成率自适应 |
