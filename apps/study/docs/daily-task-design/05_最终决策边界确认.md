# 第五轮：最终决策——完整功能边界确认

**目标**：在需求文档动笔前，各角色确认每日任务系统的最终边界，锁定 v1 做什么、不做什么  
**发言角色**：全体五人

---

**张总（主持）**：

我把前四轮的核心结论列出来，逐条请大家确认或提出最后异议。

| # | 结论 | 状态 |
|---|------|------|
| 1 | v1 固定每天一首，系统按年级顺序推荐 | 待确认 |
| 2 | 家长在设置中选年级（一年级/二年级），一次性，不需要每天操作 | 待确认 |
| 3 | 温柔 streak：显示"已坚持 X 天"，断掉不归零，改显"本月完成 X 天" | 待确认 |

---

**陈博士**：

第 3 条我要补充一个细节，不是异议：断掉之后的首次回访，文案要主动欢迎，而不是默默把数字改了。具体建议是：断掉后第一次打开 app，任务卡片顶部出现一行小字"好久不见，继续出发！"，然后正常显示今日任务。不需要弹窗、不需要打断流程，一句话温暖提示就够了。这对孩子的心理接纳很重要，让他感受到"没关系，还可以继续"。其余五条我没有异议。

---

**小林**：

第 4 条我要确认一个设计细节：任务卡片的"已坚持 X 天"，我坚持要放在卡片内部可见位置，不能藏起来。其余同意。另外我想给 v1 加一个微小但高价值的功能：任务卡片完成状态时，streak 数字要有一个小动画——数字从 N 跳到 N+1。这个动画成本极低（CSS 数字翻滚），但"看到数字变大"的瞬间对孩子的正向强化非常显著。老李，这个可以做吗？

---

**老李**：

可以做，两小时以内。CSS counter + transform 就够，不需要 JS 动画库。确认六条都没有异议，补充一个技术边界说明：

- "今日推荐"的计算逻辑：以设备首次使用日期为 Day 0，按年级诗目顺序，每天推进一首。如果当天已完成，明天自动推下一首；如果未完成，第二天仍推新一首（不补昨天的）。
- 这个逻辑纯前端可实现，但有一个边缘情况：如果用户选了年级但没有背过任何诗，第一首始终是该年级第一首。年级切换后，从新年级第一首重新开始，旧进度保留但不继续推进。这个行为需要在需求文档里写清楚，不然实现阶段会有歧义。

---

**王妈妈**：

我有一个没有在前面几轮说过的顾虑，现在提出来：每日任务的"推荐诗"顺序，一年级第一首是什么？如果第一首是《悯农》，很多孩子在幼儿园就背过，会觉得"太简单了，没意思"；如果第一首是生僻的，又会打退堂鼓。推荐顺序的合理性直接影响前三天的留存，我建议需求文档里要求内容负责人（或者对齐语文老师）审核推荐顺序，不能纯靠课标顺序来排列。

---

**张总（锁定最终边界）**：

好，综合大家意见，v1 边界最终确认：

**做：**
- 首页今日任务卡片（未完成/已完成两态）
- 温柔 streak：显示"已坚持 X 天"，断掉不归零
- 断掉回访时的温暖欢迎提示
- 完成时 streak 数字跳动动画
- 年级设置（一次性，在设置入口）
- 按年级顺序自动推进每日一首

**不做（v1 明确排除）：**
- 家长每日手选
- 智能推荐算法
- 补昨天未完成的诗
- 账号体系 / 跨设备同步
- 推送通知（依赖 PWA，v1 不做）

**遗留待确认（需求文档外）：**
- 各年级推荐诗目顺序需语文老师审核
- 角色形象视觉设计（需求文档中用占位描述）
