# 间隔复习系统 — 多角色研讨记录

日期：2026-10-10

## 背景

ProfileSheet"每日提醒时间"功能是伪功能（无后端无法实现推送），需要替换成真正对用户有价值的功能。核心命题：**纯前端 + localStorage，能做出有实际效果的复习系统吗？**

---

## 角色研讨

### 角色A — 产品经理（务实派）

> "用户背完一首诗就消失了，app对他没有后续价值。我们需要一个理由让用户每天回来。"

关键问题：
- 75首诗，一个孩子全背完要多久？按1天1首算，75天。但没有复习机制，第1周背的早忘了。
- 家长付出信任成本让孩子用这个app，他们需要看到"真的记住了"的证据，不只是背诵次数。
- Duolingo靠streak让用户每天回来。我们也可以，但streak必须和真实复习绑定，不能空刷。

结论：**复习系统是留存的核心机制，不是可选功能。**

### 角色B — 教育研究（儿童认知派）

> "儿童记忆的最大敌人不是遗忘速度，而是错误的自信。"

研究结论：
- 6-12岁儿童有70%在"觉得会了"之后实际无法完整背出（高估自己）
- 主动回忆（Active Recall）效果是被动重读的2-3倍——复习流程必须是"先尝试背，再看答案"
- 儿童无法区分"稍微会"和"很会"，5档评分完全失效，4档Anki体系也太复杂
- **最可靠的方案：不让儿童自评，通过行为数据判断**（答对/答错，而不是"感觉"）

结论：**复习必须有验证步骤，不能是孩子自己按"我会了"。**

### 角色C — 技术实现（约束派）

> "我们有localStorage，75首诗，没有后端。能做的事情其实很清晰。"

约束清单：
- ✅ 记录每首诗的背诵时间、评星、复习次数 → localStorage
- ✅ 固定间隔阶梯计算下次复习日期 → 纯JS Date运算
- ✅ 每日到期复习列表 → 过滤`due <= today`的卡片
- ❌ SM-2动态算法 → 依赖精准自评，儿童输入不可靠，放弃
- ❌ 服务端推送提醒 → 无后端，放弃
- ⚠️ 防蒙混验证 → 3选1的"下一句"选择题，伪随机干扰项取其他诗的句子

技术方案：固定5档间隔阶梯 + 3选1验证 + localStorage持久化

结论：**SM-2过于复杂且依赖不可靠的自评，固定阶梯更适合此场景。**

## 竞品分析结论

| 维度 | Anki | Duolingo | 我们的方案 |
|------|------|----------|-----------|
| 评分机制 | 4档（Again/Hard/Good/Easy） | 隐式（答题对错） | 2档（通过/未通过）|
| 防蒙混 | 无 | 系统控制答题 | 3选1验证 |
| 每日上限 | 无 | 有（每日目标） | 3复习+1新诗 |
| 积压处理 | 全部显示（恐怖） | 顺延不显示数字 | 顺延不显示数字 |
| 儿童友好 | 差 | 好 | 针对优化 |

## 算法研究结论

**推荐方案：固定5档间隔阶梯**

```
背诵后 → 第1档：1天后复习
复习通过 → 第2档：3天后复习
复习通过 → 第3档：7天后复习
复习通过 → 第4档：15天后复习
复习通过 → 第5档：30天后复习 → 标记"已掌握"

任意档位复习未通过 → 退回第1档，重新开始
```

**每日限制**
- 复习：最多3首/天（超出部分顺延，不显示积压数字）
- 新诗：最多1首/天（复习清零后才推荐）

---

## 最终决策

1. ProfileSheet"每日提醒"区域改为**学习统计**（已背/已掌握/连续天数）
2. 新增间隔复习数据结构`ReviewCard`，存入`poem_review_cards` localStorage key
3. 首页改造：今日复习（最多3首）+ 学新诗（1首）
4. 复习流程复用MemorizeMode，结束后加3选1验证步骤
5. 通过/未通过自动更新ReviewCard的档位和due日期
