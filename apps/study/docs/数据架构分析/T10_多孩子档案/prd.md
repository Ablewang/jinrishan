# T10 · 多孩子档案（localStorage key 前缀隔离）

**类型：** 新功能  
**优先级：** P2  
**估算工时：** 3–4天  
**UI改动：** 首页顶部头像入口；Profile Picker 底部弹窗；新建档案流程

---

## 背景

家里两个孩子共用一台设备学古诗，当前只能共享一份进度，无法分开追踪。`poem_nickname` 字段预示了多用户概念，但未实现。

---

## 需求

### 数据方案

**全局 key（不加前缀，共享）：**
- `poem_profiles`：Profile 列表
- `poem_active_profile`：当前激活的 profileId

**用户 key（加 `{profileId}:` 前缀）：**
- 其余所有12个核心 key 均加前缀

**Profile 结构：**
```ts
interface Profile {
  id: string        // 'p1', 'p2', ...
  name: string      // '小明'
  avatar: string    // emoji，从预设列表选择
  createdAt: string // ISO 日期
}
```

### 功能需求

1. **切换档案**：首页顶部右侧头像气泡，点击弹出 Profile Picker
2. **新建档案**：Profile Picker 内"+ 添加孩子"，进入起名 + 头像选择流程
3. **切换生效**：切换后强制刷新页面（`window.location.reload()`），确保所有 hook 重新初始化
4. **旧数据迁移**：首次运行时，检测无前缀旧数据，自动迁移到 `default` profile，删除无前缀 key

### 非功能需求

- 最多支持 5 个档案（超过后"+ 添加孩子"灰化）
- 删除档案时二次确认，删除后该档案所有 key 从 localStorage 清除

## 界面设计要点

**首页顶部头像气泡（右上角）：**
```
  [小明 ▾]   ← 点击展开
```

**Profile Picker 底部弹窗：**
```
┌─────────────────────────────────────┐
│  选择孩子                             │
│─────────────────────────────────────│
│  🦁  小明       ✓（当前）             │
│  🐼  小红                            │
│─────────────────────────────────────│
│  + 添加孩子                           │
└─────────────────────────────────────┘
```

**新建档案流程（两步）：**
```
第1步：输入名字
[          小名          ]

第2步：选头像
🦁 🐼 🐯 🐻 🦊 🐰 🐸 🐧 🦋 🌟
```

---

## 验收标准

- [ ] 切换档案后，首页数据切换为对应孩子的进度
- [ ] 新建档案后，进度从零开始，不继承其他档案数据
- [ ] 旧用户升级后，数据自动迁移到 `default` 档案，进度不丢失
- [ ] 删除档案后，对应 localStorage key 全部清除
- [ ] 最多5个档案，超出后无法新建
- [ ] 切换档案时页面刷新，不出现数据混用
