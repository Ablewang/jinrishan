## 第一部分：立即可做，无需新增数据

### 1. 智能每日计划（P1）

**现状痛点：** 用户必须手动维护 `poem_queue`，孩子不知道该背哪首。

**算法逻辑（`src/lib/dailyPlan.ts`）：**

- Step 1 — 复习优先：从 `poem_review_cards` 取 `due <= today && level < 5`，最多 3 首
- Step 2 — 选新诗：`poem_queue` 中第一首；若队列为空，按 id 升序取第一首未背过的诗
- Step 3 — 难诗插队：`review_schedules` 中 ef < 1.8 且 7 天内没背过的，最多插 1 首

```ts
// src/lib/dailyPlan.ts
export interface DailyPlan {
  reviewPoems: number[]   // 今日到期复习
  newPoem: number | null  // 新诗
  focusPoem: number | null // 难诗加强
}

export function buildDailyPlan(
  today: string,
  reviewCards: ReviewCard[],
  queue: number[],
  progress: Record<number, PoemProgress>,
  schedules: Record<number, ReviewSchedule>,
  allPoemIds: number[],
): DailyPlan {
  const reviewPoems = reviewCards
    .filter(c => c.due <= today && c.level < 5)
    .sort((a, b) => a.due.localeCompare(b.due))
    .slice(0, 3)
    .map(c => c.id)

  const newPoem = queue[0]
    ?? allPoemIds.find(id => !progress[id]?.memorized) ?? null

  const sevenDaysAgo = new Date(today)
  sevenDaysAgo.setDate(sevenDaysAgo.getDate() - 7)
  const cutoff = sevenDaysAgo.toISOString().slice(0, 10)
  const focusPoem = Object.values(schedules)
    .filter(s => s.ef < 1.8 && s.nextReviewDate > cutoff)
    .sort((a, b) => a.ef - b.ef)[0]?.poemId ?? null

  return { reviewPoems, newPoem, focusPoem }
}
```

**改动范围：** 新增 `dailyPlan.ts`；`Home.tsx` 中用 `buildDailyPlan` 替换 `queue[0]` 的硬读取。手动排队与自动计划共存，手动设置优先。

### 2. 难诗重点突破模式（P1）

**数据基础：** `review_schedules[poemId].ef` 已存储，ef < 1.8 表示反复出错。

**实现思路：**
- 遍历 `review_schedules`，筛选 `ef < 1.9 && totalSessions > 0`，按 ef 升序排列
- 从 `recitation_sessions` 统计每首诗中 `lines[].hintCount > 2` 的行，作为"高频出错行"
- `ProgressPage.tsx` 新增"攻坚榜"板块，列出 Top 3 难诗
- 背诵页新增 URL 参数 `?mode=focus`：关闭自动提示、高亮错行、完成后显示 ef 变化正反馈

### 3. 每周学习报告（P1）

| 报告字段 | 数据来源 |
|---|---|
| 本周背了几首 | `poem_memorize_history` 按 date 过滤上周范围 |

| 连续打卡天数 | `poem_streak.count` |
| 本周最难的诗 | `review_schedules` 中 ef 最低的已背诗 |
| 本周满星首数 | `poem_progress` 中 bestStars===3 的计数 |
| 累计字数 | `poem_total_chars` |

**触发方式：** 新增路由 `/weekly-report`；每次打开 App 时检查 `poem_last_report_week`，若上周有数据但未看本周报告，首页显示红点提示。

### 4. 分享卡片增强（P2）

**新增卡片类型：**

- **里程碑卡**：背诵数突破 10/20/35/50/70 时自动弹出，内容「刚刚背完第 N 首！」+ 等级称号
- **满星成就卡**：首次 3 星通过时触发，内容「无提示背完《XXX》！」+ 诗的第一行
- **周报摘要卡**：本周背了几首 + 连续天数 + 最难克服的诗

**技术改动：** `ShareCardContext` 的 `params.type` 扩展为 `'poem' | 'checkin' | 'milestone' | 'weekly' | 'perfect'`

## 第二部分：少量新增数据采集

### 5. 中途放弃记录（P3）

**新增字段**（加入 `RecitationSession`）：
```ts
abandoned: boolean
abandonedAtLine: number | null
```

背诵页点击返回时调用 `saveResult` 并标记 `abandoned: true`，不触发 SM-2 的 ef 更新。

**应用：** 放弃次数 > 3 的诗优先进入攻坚榜；每周报告中「这首诗卡了你 N 次，今天要不要再试？」。

---

### 6. 注释展开行为追踪（P4）

新增 `poem_annotation_opens: Record<poemId, count>`。每次展开注释面板时对应 poemId 计数 +1。注释展开多的诗纳入"理解薄弱诗"维度。

## 第三部分：多孩子支持方案

### 7. localStorage Key 前缀隔离（P2）

```ts
// src/lib/storageKey.ts
const ACTIVE_PROFILE_KEY = 'poem_active_profile'

export function getStorageKey(rawKey: string): string {
  try {
    const profileId = localStorage.getItem(ACTIVE_PROFILE_KEY) ?? 'default'
    return `${profileId}:${rawKey}`
  } catch {
    return rawKey
  }
}
```

**Profile 数据结构：**
```ts
interface Profile {
  id: string        // 'p1', 'p2', ...
  name: string      // '小明'
  avatar: string    // '🦁'
  createdAt: string // ISO 日期
}
// 存于 poem_profiles（不加前缀，全局共享）
// 当前用户存于 poem_active_profile（不加前缀）
```

**旧数据迁移：** 首次运行时检测无前缀旧数据，调用 `migrateToProfile('default')` 自动迁移，再删除旧 key。

**UI：** 首页顶部头像气泡 → 底部弹窗 Profile Picker → 新增档案时进入起名 + 头像选择流程。

**关键实现注意：** 切换档案后需用 `key={activeProfileId}` 强制重置根组件，确保所有 hook 的 useState 重新初始化。

## 第四部分：PWA 推送通知方案

### 8. 推送通知完整实现（P2）

`reminder_time` 字段已存，缺少真正推送的三件套：Service Worker + Push API + 推送后端。

**方案 A：纯前端 Periodic Background Sync（无后端，仅 Android Chrome）**
- 安装 `public/sw.js`，注册 `periodicsync` 事件
- 限制：iOS Safari 不支持，App 完全关闭时无法触发

**方案 B：Web Push Protocol（推荐，需轻量后端）**

```
前端                        后端（Cloudflare Worker + D1）
  │                                │
  ├─ requestPermission()           │
  ├─ subscribe(pushManager) ──────►│ 存储 {endpoint, keys, reminder_time}
  │                                │
  │                     Cron每分钟 │
  │◄── Push Message ───────────────┤ 调用 Web Push 协议
  │                                │
  SW 收到 push 事件                 │
  显示通知：「古诗小课堂·今日打卡」   │
```

**通知内容设计：**
- 标题：「古诗小课堂 · 今日打卡」
- 正文备选池：「今天有 N 首到期复习」/「连续第 X 天！别中断」
- 点击通知 → 直达首页今日任务
- 推荐技术栈：Cloudflare Workers + D1 + `web-push` npm 包，几乎零成本

## 推荐落地顺序

1. **第1周** — 智能每日计划 + 难诗突破入口（纯算法，改动最小）
2. **第2周** — 每周学习报告页面（新增 `/weekly-report` 路由 + 分享卡扩展）
3. **第3周** — 多孩子档案系统（注意旧数据迁移，防止数据丢失）
4. **第4周** — PWA 推送（Android 方案先行；iOS + 后端推送按需排期）
5. **后续迭代** — 放弃记录 + 注释追踪（数据采集期，3个月后基于信号优化推荐）

## 关键实现注意

**两套进度系统的联合查询：** 难诗突破模式需要联合 `useProgress`（ReviewCard）和 `useRecitation`（SM-2 ef值），建议新增 `src/lib/difficultyAnalysis.ts` 聚合层，不修改现有 hook。

**localStorage 容量：** `recitation_sessions` 无上限，长期使用会增长。建议保存时检查：会话数 > 500 则 trim 最老 200 条。
